# Как участвовать и как выпускать версии

Писать в issues и pull request'ах можно по-русски и по-английски.

Присылая правку, вы соглашаетесь, что она войдёт в проект на тех же условиях —
[PolyForm Noncommercial 1.0.0](LICENSE). Приложение делается бесплатным для всех,
кто варит кофе, и зарабатывать на нём не должен никто.

## Среда

- JDK 21;
- Android SDK: платформа `android-37`, build-tools `36.0.0`;
- Gradle идёт в комплекте (wrapper), отдельно ставить не нужно.

```bash
./gradlew testDebugUnitTest      # модульные тесты
./gradlew assembleDebug          # отладочная сборка
./gradlew connectedAndroidTest   # тесты миграций базы, нужен телефон или эмулятор
```

## Код

- Комментарии и сообщения коммитов — по-русски, как в существующем коде.
  Комментарий объясняет, **почему** так сделано; что делает строка, видно из неё
  самой.
- Идентификаторы и строки ресурсов — по-английски; тексты интерфейса живут в
  `app/src/main/res/values/strings.xml` и `values-ru/strings.xml`, обе локали
  обязательны.
- Логику, которую можно проверить без Android, выносим в чистые функции и
  классы и покрываем модульными тестами (`app/src/test`).
- Изменения схемы базы — только с новой версией и миграцией; экспортированные
  схемы лежат в `app/schemas` и коммитятся вместе с миграцией.

## Ключ подписи

Релизная сборка подписывается ключом, путь и пароли к которому лежат в
`../keystore/keystore.properties` — рядом с репозиторием, но **не в нём**:

```properties
storeFile=/полный/путь/pourista.jks
storePassword=…
keyAlias=pourista
keyPassword=…
```

Если файла нет, `assembleRelease` соберёт неподписанный APK и не упадёт. Ключ
терять нельзя: подписанное другим ключом обновление не встанет поверх
установленного приложения.

## Выпуск версии

1. Поднять `versionCode` и `versionName` в `app/build.gradle.kts`.
2. Записать изменения в `CHANGELOG.md`, а короткую выжимку — строкой
   `notes_<версия>` и записью в `ui/ReleaseNotes.kt`: их показывает окно
   «Что нового».
3. Прогнать тесты и собрать релиз:

   ```bash
   ./gradlew testDebugUnitTest assembleRelease
   ```

4. Проверить, что собралось именно то:

   ```bash
   $ANDROID_HOME/build-tools/36.0.0/aapt2 dump badging \
       app/build/outputs/apk/release/app-release.apk | head -3
   apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
   ```

5. Поставить APK на телефон и проверить руками главное: подключение к весам,
   тару, дозирование, полный пролив по рецепту с автофинишем, запись в историю.
6. Поставить тег и выложить релиз:

   ```bash
   git tag -a v1.0.0 -m "Pourista 1.0.0"
   git push origin v1.0.0
   ```

   Затем создать релиз на GitHub с описанием из `CHANGELOG.md` и приложить APK,
   переименованный в `pourista-1.0.0.apk`.

Сборка релиза в CI намеренно не делается: для этого пришлось бы держать ключ
подписи в секретах GitHub. Релизный APK собирается на машине автора.
